Project Progress

Where the project stands, what shipped recently, and what is still being decided. The source of truth is the milestones on GitHub. This page is a summary of them.

Last updated Nov 19, 2026

At a Glance

  • The tool is live. It runs at accessibilityenhancer.com/app, on AWS in us-east-1: the website on ECS, each uploaded deck processed by a Lambda, files in S3 and submissions in DynamoDB. Every merge to main deploys from CI, once a reviewer approves it.
  • PowerPoint is working end to end. Reading order is fixed by role, missing image descriptions are written, the presentation language is set, and table header rows are turned on. Slides with no title, low contrast, text under 9 pt, vague link text and shapes read out of visual order are reported rather than guessed at.
  • Every file comes back with a scored report. It opens with a score out of 100 for the file as it was uploaded, marks each problem critical, serious, moderate or minor with its WCAG 2.1 criterion, and lists every change with the value before and after.
  • Image descriptions come from Claude on Amazon Bedrock (Claude Haiku 4.5 by default), which gets each picture along with up to 400 characters of the slide's own text as context. The local 4.4 GB model is gone, and no GPU is needed (#97).
  • PDFs work when you run the tool yourself, but not yet on the live site. The pipeline rebuilds them as tagged PDFs, with OCR for scanned pages, and stops for a person whenever it is unsure. Only the PowerPoint pipeline runs on AWS so far, so the hosted version turns PDFs away with a message.
  • There is still no sign-in. The Cognito user pool, its sign-in pages and its email are in the Terraform (#140), but the app does not use them yet, so visitors are still told apart by a signed browser cookie (#77).

Recently Shipped

  • Sign-in infrastructure (Nov 19). A Cognito user pool with hosted sign-in pages, email and password, Google when it is configured, and verification email through SES. The app's half of sign-in is the part still to come. #140
  • Backups and retention (Nov 19). Both S3 buckets are versioned, so a file that is deleted or overwritten can be restored for 3 days, and the submissions table can be restored to any second in the last 35 days. Uploads expire after 7 days and results after 30: a deck is a working file, not a record. #138
  • Live on AWS (Nov 19). The website moved to ECS Express Mode, which brings its own load balancer and certificate, and CI now builds both container images and applies the Terraform on every merge to main. Each deployed version is a named commit, so a rollback is re-running an older deploy. #131, #132
  • A clearer upload and report (Nov 19). Files can be added to the upload list a few at a time and removed one by one, and the report is now a page with a summary and a slide-by-slide view, as well as a text file to download. #130
  • Alt text from Claude on Amazon Bedrock (Nov 5). The AWS work came onto main: descriptions are written by a hosted model, and the local vision model, torch and transformers were removed with it. #125
  • The web app audits itself in CI (Nov 1). Every page and state is loaded in headless Chromium and checked with axe-core on every pull request. There are no WCAG 2.1 Level A or AA violations. #108, #123
  • Reading order by role, and before and after in the report (Oct 31). Shapes are ordered title, then subtitle, then the content in the author's own order, then date, footer and slide number. A shape that sits above another but is read after it is reported. Every change is listed with the value before and after. #119, #122
  • Table header rows, contrast, small text and link text (Oct 29 to Oct 31). A table whose first row reads as headings gets the header row option turned on. Text below 4.5:1, text under 9 pt, and link text that does not say where the link goes are reported, each with a severity and a WCAG criterion. #115, #106, #109, #105
  • Uploads survive a restart (Oct 29). The original file is never moved, so a retry or a restart picks the file up again from it instead of leaving it stuck as processing. Every form also carries a CSRF token now. #99, #96
  • PDF remediation (Oct 26). PDFs go through a page-by-page pipeline and come back as tagged PDFs, with OCR for scanned pages and human review for anything uncertain. #84, #92

The test suite is past 270 tests, covering both pipelines, every page and route of the web app, and the AWS storage layer against stand-ins for Bedrock, S3 and DynamoDB, so it still runs in seconds without AWS credentials.

Open Decisions

  • Which ways to sign in. Email and password and Google are built. Cognito checks a token against one exact issuer, and Microsoft's multi-tenant endpoints put each tenant's own id in the issuer, so one Microsoft provider can only serve one tenant: UW's, or personal accounts. UW NetID comes later. #77
  • How to check problems that only show once a page is rendered, such as CSS contrast, keyboard access and focus order. Most of the WCAG criteria still uncovered need this. #47
  • How long to keep files, and where people are told. Uploads go after 7 days and results after 30, which may not be the right period. #78
  • Whether to process more than one file at a time. It needs a shared queue and shared progress outside the process, so for now one server works through one file at a time. #104
  • How the tool compares with existing checkers on real decks, which has not been measured yet. #98

Settled since the last update

  • Alt text comes from a hosted model. Claude on Amazon Bedrock, not a model running locally. The 4.4 GB download and the need for a GPU went with it. #97
  • No workflow engine, for now. Putting a deck in S3 is what starts a Lambda, status and progress are in DynamoDB, and failures raise CloudWatch alarms, so there is no queue left for n8n to take over. #80
