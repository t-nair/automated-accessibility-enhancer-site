Automated Accessibility Enhancer

An open-source tool that fixes common accessibility problems in PowerPoint files. It puts slide titles first in the reading order, adds alt text to images that don't have any, sets the presentation language, and gives back a report that scores the file and lists everything a person still needs to look at. PDFs are rebuilt as tagged PDFs when you run the tool on your own machine.

How It Works

The tool is written in Python and uses python-pptx to edit files directly. Files can come in three ways, and all of them go through the same pipeline. On the live site nothing is processed by the website itself: an upload goes to S3, which starts the pipeline on AWS Lambda.

Input

  • Web uploadFlask site
  • Folderz_reorder.py
  • S3 bucketStarts the pipeline on AWS Lambda

Pipeline

  1. ConvertOlder .ppt files are converted to .pptx with LibreOffice
  2. Fix reading orderTitle first, then subtitle, then the content in the author's order, then date, footer and slide number
  3. Add alt textImages without alt text are described by Claude on Amazon Bedrock, using the slide's text as context
  4. Check the restLanguage, missing titles, contrast, font size, link text and table headers

Output

  • Fixed fileA .pptx, or a tagged PDF, ready to download
  • Scored reportA score out of 100, every change before and after, and each problem by severity

Current Limitations

  • Title detection can miss unusual layouts. When a slide has no real title placeholder, a small trained model guesses the title from size, position and wording. A title that is an image is not found.
  • Generated alt text needs to be reviewed. Models can get names, dates, and text inside diagrams wrong. The report lists every description so they can be checked.
  • Technical diagrams are hard to describe. Earlier tests with free tools like alternat did not produce usable alt text for engineering figures.
  • Some problems are reported, not fixed. A missing title, a colour with too little contrast, a font size and the wording of a link are design decisions, so the report names each one and leaves it to a person.
  • PDFs only work when you run the tool yourself. On the live site PDF uploads are turned away with a message, because only the PowerPoint pipeline runs on AWS so far.
  • There are no user accounts yet. Files are kept separate with a signed browser cookie, which is not real security. The Cognito user pool is built, but the app does not use it yet (#77).
  • Files are processed one at a time. A restart is safe now, because the original upload is never moved and unfinished files are queued again, but running several at once needs a shared queue (#104).
  • Each file can be up to 50 MB, and one upload is limited to about 100 MB on the live site because of the proxy in front of it.
  • Web pages are not supported. Only PowerPoint and PDF are checked today; HTML is planned (#41).
